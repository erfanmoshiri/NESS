## E11-a — Encoder ablation (design choice) — DONE

**Setup:** NESS, ogbn-arxiv, MCAR @ 80%, lr=0.001, hidden=128, view2=ppr,
ssl={hist,path}, contrastive on. One-factor swap: encoder conv type.

| Encoder | Test Macro-F1 | Test Acc | Notes |
|---|---|---|---|
| GCN  | 0.354* | 0.619* | old default; blends self+neighbors → washes out FP-prefill (*cls-only proxy) |
| GAT  | 0.388  | 0.633  | early-stopped ep540; no clean self-channel |
| **SAGE** | **0.400** | **0.637** | **chosen** — self-transform preserves per-node FP-prefill signal |

**Finding:** SAGE wins. Its explicit self-transform (W1·x_i + W2·mean(neigh))
preserves the FP-prefilled per-node features that GCN/GAT dilute — the change
that restored NESS to a win over FP. → **encoder = SAGE, locked.**

*GCN row is cls-only (0.354); GAT/SAGE are full config. Re-run GCN full-config
for a perfectly matched table before publishing.*

## E11-b — Hidden width (HP sensitivity) — DONE

**Setup:** NESS SAGE full (ppr + hist,path) vs FP, arxiv MCAR @ 80%, fair lr.

| Model | width | Test Macro-F1 | Test Acc |
|---|---|---|---|
| FP        | 128 | 0.388 | 0.641 |
| FP        | 256 | 0.397 | 0.645 |
| NESS-SAGE | 128 | 0.400 | 0.637 |
| NESS-SAGE | 256 | **0.410** | **0.642** |

**Finding:** NESS beats FP at both widths; margin stable (+0.012 @128, +0.013
@256). Width costs ~0.01 F1 symmetrically → comparison fair. 128 = fast default;
256 for headline numbers if desired.

## E11-c — Component ablation (SSL / clustering) — PARTIAL

**Setup:** NESS SAGE, arxiv MCAR @ 80%, fair lr, hidden=256.

| Config | Test Macro-F1 | Test Acc |
|---|---|---|
| cls-only (no SSL, no contrastive) | 0.401 | 0.633 |
| full (ppr + hist,path + contrastive) | 0.410 | 0.642 |

**Finding:** SSL + contrastive add ~+0.009 over a well-configured bare encoder.
Small + single-seed → needs multi-seed (E2) before claiming. Direction correct
(helps, at high missingness).

**Clustering granularity (GCN cls-only, older, reference only):**
num_parts=5 → 0.340, num_parts=20 → 0.354. Fewer clusters did *not* help →
clustering is not the bottleneck (the encoder was).
