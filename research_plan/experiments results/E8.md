## E8-a — Anchor factor-flips (on OLD locked config w_cls=1, 2-layer)
Each run flips one axis of the anchor objective vs shared base.

| config | Test F1 | Δ vs base |
|---|---|---|
| anchor_base (varying, resampled, global) | 0.4273 | — |
| F1_fixed (per-node, fixed input) | 0.4384 | +0.011 |
| F2_frozen (static landmarks) | 0.4333 | +0.006 |
| F3_local (local reach) | ~0.427 | ~0 |

**Finding:** the "input-varying" hypothesis is **refuted** — the *fixed* (per-node) form
beats the varying (pairwise) form. Stochasticity/input-variation is NOT the factor.
This motivated the per-node classification objective (anchorcls).

## E8-b — Why the anchor loss is inert (loss-magnitude diagnosis, from E3)
Loss trajectories across objectives revealed the real pattern:

| objective | loss start→end | scale | helps? |
|---|---|---|---|
| hist | 2.76 → 0.88 | large, keeps dropping | ✅ +0.018 |
| path | 0.69 → 0.39 | large, drops | ✗ (drops but not class-relevant) |
| triplet | 1.01 → 0.38 | large, drops | ✗ hurts |
| anchor | 0.026 → 0.019 | **tiny, flat** | ✗ trivial target |
| centroid/stats/recon | ~0.01–0.04, flat | tiny | ✗ inert |

**Finding:** helpful ⟺ (hard target that keeps dropping) AND (class-relevant). anchor's
MSE-of-distance-differences target is trivially small → no teaching signal. hist has both
properties. path/triplet are hard but not class-relevant.

## E8-c — anchorcls: a harder, class-relevant anchor objective
Probe (probe_anchor_class.py) confirmed anchor-distance IS class-relevant:
**macro-F1 0.207 / acc 0.50 from 32 landmark distances alone** (11× random; 72% of full
feature F1). So the signal exists. Built `anchorcls` = per-node hop-bucket CLASSIFICATION of
landmark distances (loss starts 1.66, drops to ~0.83 — genuinely hard, unlike old anchor).

**Then tried every lever to make it help downstream — none did:**

| lever | result | vs no_anchor (0.4367) |
|---|---|---|
| anchorcls w_anchor=1 | 0.4228 | −0.014 |
| anchorcls w_anchor=3 | 0.4350 | −0.002 |
| anchorcls w_anchor=5 | 0.4307 | −0.006 |
| anchorcls w_anchor=8 | 0.4343 | −0.002 |
| anchorcls w3 + projection head | 0.4330 | −0.004 (loss floor 0.83→0.82: **not** capacity) |
| anchorcls w3 + SSL warmup (100 ep) | 0.4381 | +0.001 (parity, not gain) |
| anchorcls w3 @ width 256 | 0.4585 | −0.005 vs no_ssl_256 (0.4634) — same story at 256 |

**Finding:** no weighting, no projection head (capacity ruled out — loss floor unchanged),
no SSL-first warmup (ordering ruled out — warmup only reached parity) makes structural SSL
beat the no-SSL baseline at 80%. Conclusive.

## The mechanism (why loss drops a bit but doesn't help)
The anchorcls loss falls 1.66→0.83 then floors. Decomposition:
- **Reducible part (the drop):** coarse near/far structure **already captured by FP-prefill +
  SAGE aggregation** → fitting it trains the read-out head without reshaping z → redundant.
- **Irreducible part (the 0.83 floor):** fine global-positional detail a 3-hop local encoder
  **cannot compute** → unlearnable regardless of objective. Projection head not lowering the
  floor confirms this is inherent, not a z-capacity limit.
So the loss can fall modestly while adding zero class-useful representational content.

**Status:** DONE. This is the negative-result core feeding the RQ3 synthesis (see SSL_SYNTHESIS.md).
